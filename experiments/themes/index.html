Metronome UI experiments

Four takes on the same app, each pushing past the current restrained UI in a different direction. Every one keeps the whole feature set and the pure-logic block byte-identical to index.html — only the presentation layer differs. Open any of them straight from disk.

01

Pulse Engine

A physical unit sitting on the desk — machined chassis, an inset LCD, and a transport button you can hit without looking.

  • The tempo readout and the beat strip are housed in one recessed panel, so the two things you glance at are literally one object.
  • Beat dots become lit bars in a sunken housing; accents get a red cap.
  • The unit's whole bezel flashes on every audible beat, harder on accents.
  • Bevelled surfaces, recessed fields, raised keys, a round amber transport that turns red while running.
Variance 8 · Motion 6 · Signature: the display window
02

Kinetic Type

Editorial and near-monochrome. The number carries the whole page, and colour is reserved for one meaning only.

  • Display-scale BPM with the unit set vertically beside it; the number and the beat strip hang on one shared measure line.
  • Amber appears only when something is live — the active mode, a lit beat, the running transport. Everything else is ink on black.
  • Accented beats are encoded as tick height rather than a ring, so the bar stays countable at a glance.
  • Parameters read as a spec sheet: label left, control right, hairline rules between.
Variance 9 · Motion 5 · Signature: the vertical unit label
03

Pulse Field

Built for a dim room and a guitar in your hands. The beat stops being a dot and becomes light on the page.

  • Every audible beat blooms the canvas behind the readout — readable from across the room, in peripheral vision, without focusing on it.
  • Beat orbs glow hard on the strike and decay slowly, like a real LED.
  • Soft elevated surfaces, a floating pill mode selector, generous air.
  • The one variant where the glow is the affordance rather than decoration.
Variance 8 · Motion 7 · Signature: the canvas bloom
04

Grid Console

A technical instrument. Everything sits on an exposed grid, and nothing is rounded.

  • Two-column console above 880px — the tempo readout stays fixed in view while you edit a practice phase beside it.
  • Hairline grid, mono numerals throughout, corner register marks framing the primary readout.
  • Parameters read as a table with a label gutter, not a stack of cards.
  • Collapses to a single stacked column on narrow screens.
Variance 8 · Motion 3 · Signature: register marks + exposed grid

Shared across all four

Performance mode. While the metronome runs, the settings recede and the readout takes the room. Hovering or focusing any panel brings it straight back, so nothing is ever unreachable.

Strike and decay. Beat feedback now hits in 30ms and fades over 300–500ms instead of blinking symmetrically — much closer to how a real metronome LED reads, and it still clears its own pulse class through transitionend exactly as before.

Nothing structural changed. The LOGIC-BEGIN/LOGIC-END block is byte-identical to the shipped app in every variant, and the lookahead scheduler's capture-before-advance pattern is untouched. The only added JS is a transport-state class and a per-beat flash hook, both called from inside the existing gated callback.

These are disposable explorations, not candidates to merge as-is. Pick a direction (or pieces of several) and it can be folded back into index.html properly.
